DCM

DcmDsd

DcmDsd（Diagnostic Service Dispatcher，诊断服务分发单元）负责路由和分发收到的诊断请求。它根据请求报文的第一个字节（SID，Service Identifier）找到对应的处理函数。

其下的 DcmDsdServiceTable 中列出了该 ECU 支持的所有 UDS 服务（SID），每个服务节点（如 ReadDataById、EcuReset 等）代表一个具体的诊断服务，其下还会包含该服务支持的子服务（SubService），例如：

  • DiagSessionControl（0x10）下包含 DefaultSession、ProgrammingSession、ExtendedSession 等子服务。
  • SecurityAccess（0x27）下包含 SeedRequest、KeySend 等子服务。
  • EcuReset（0x11）下包含 HardReset、KeyOffOnReset、SoftReset 等子服务。

Dsd Sid Tab Session Level Ref 会话等级引用 引用该服务可用的诊断会话等级（Session Level）。只有处于指定会话状态下，测试仪才能调用此服务。 截图中引用了两个会话：
- Default（默认会话）
- Extended（扩展会话）
表示 0x14 服务在默认会话和扩展会话下均可使用。
Dsd Sid Tab Vehicle System Group Ref 车辆系统组引用 用于定义该服务属于哪个车辆系统组，在多 ECU 系统中用于路由或访问控制。 通常保持为空，仅在复杂的多 ECU 诊断路由场景中使用。
Dsd Service Role Ref 服务角色引用 指定该服务在 DCM 中的角色（Role），用于更细粒度的访问控制。 通常保持为空，使用默认角色。

  2. 会话与安全等级的逻辑：

    • Session Level Ref 决定了服务在哪些会话状态下可用。
    • Security Level Ref 决定了服务是否需要安全解锁才能使用。
    • 两者共同构成服务的访问控制策略。

  3. ClearDiagInfo 的典型配置：

    参数 典型配置 说明
    Dsd Sid Tab Session Level Ref Default + Extended 默认和扩展会话均可使用
    Dsd Sid Tab Security Level Ref 通常引用 DcmSecurityLevel（如 SecurityLevel_1） 大多数项目要求先解锁安全访问才能清除 DTC
    Dsd Sid Tab Subfunc Avail ✅ 启用 0x14 支持按 DTC 状态掩码清除
    Dsd Sid Tab Used ✅ 勾选 启用该服务

  4. 会话等级的典型配置：

    • Default：默认会话，ECU 上电后的初始状态。
    • Programming：编程会话，用于软件刷写。
    • Extended：扩展会话，用于特殊诊断功能。

  5. 截图中 Dsd Sid Tab Security Level Ref 和 Dsd Service Role Ref 未配置（显示 Use '+' to add parameters），表示当前服务未设置安全访问等级和服务角色限制。

DcmDsdSubService 实例

DcmDsdSubService 用于配置某个 UDS 服务下具体子服务（SubService） 的详细参数。例如，EcuReset（0x11）服务下包含 hardReset（0x01）、keyOffOnReset（0x02）、softReset（0x03）等子服务。

参数名称 中文直译 / 作用 详细解释 配置要点 / 注意事项
Short Name 短名称 该子服务配置实例的唯一标识名。 工具自动生成或手动命名，通常表示该子服务的具体功能，如 hardReset。截图中未显示具体名称。
Dsd Sub Service Fnc 子服务功能 指定该子服务的处理函数，即当收到该子服务请求时，DCM 应调用哪个具体函数来执行操作。 通常由工具链根据配置自动映射到 DcmDsp 层的实现函数。一般不需要手动配置。
Dsd Sub Service Id 子服务 ID 该子服务的子功能 ID（SubFunction ID），即 UDS 协议中 SID 后面的第二个字节。 必须正确配置，与 UDS 协议定义一致。截图中为 0x1。
Dsd Sub Service Mode Rule Ref 子服务模式规则引用 引用该子服务所处的诊断模式规则，用于定义该子服务在哪些诊断模式下可用。 通常保持默认，不常修改。
Dsd Sub Service Role Ref 子服务角色引用 指定该子服务在 DCM 中的角色（Role），用于更细粒度的访问控制。 通常保持为空，使用默认角色。
Dsd Sub Service Security Level Ref 子服务安全等级引用 引用该子服务所需的安全访问等级。只有通过了对应安全等级验证的测试仪才能调用此子服务。 - 如果该子服务需要安全解锁才能使用，需在此引用对应的 DcmSecurityLevel。
- 如果无需安全验证，则保持为空。
Dsd Sub Service Session Level Ref 子服务会话等级引用 引用该子服务可用的诊断会话等级。只有处于指定会话状态下，测试仪才能调用此子服务。 截图中引用了 Extended（扩展会话），表示该子服务仅在扩展会话下可用。
Dsd Sub Service Vehicle System Group Ref 子服务车辆系统组引用 用于定义该子服务属于哪个车辆系统组，在多 ECU 系统中用于路由或访问控制。 通常保持为空。

  1. 服务与子服务的关系：

    • 服务（Service）：由 SID 标识，如 EcuReset = 0x11。
    • 子服务（SubService）：由 SubFunction ID 标识，如 hardReset = 0x01。
    • 一个服务下可以有多个子服务，每个子服务可以独立配置会话/安全等级。

  2. 子服务 ID 的典型值（以 0x11 EcuReset 为例）：

    子服务名称 SubFunction ID 说明
    hardReset 0x01 硬件复位（ECU 完全重启）
    keyOffOnReset 0x02 钥匙关/开复位（模拟点火循环）
    softReset 0x03 软件复位（不重新初始化硬件）
    enableRapidPowerShutDown 0x04 快速断电（用于快速关机）

  3. 独立配置的意义：同一个 UDS 服务下的不同子服务，可能具有不同的访问控制策略。例如：

    • hardReset（0x01）可能需要安全解锁后才能执行。
    • enableRapidPowerShutDown（0x04）可能只在扩展会话下可用。
    • 通过 Dsd Sub Service Session Level Ref 和 Dsd Sub Service Security Level Ref 可以实现这种精细控制。

  4. 配置的含义：

    • Dsd Sub Service Id = 0x1：当前配置的是该服务下的第一个子服务（如 hardReset）。
    • Dsd Sub Service Session Level Ref = Extended：该子服务仅在扩展会话（Extended Session）下可用，在默认会话下会被拒绝。
    • Dsd Sub Service Security Level Ref 未配置（为空）：该子服务无需安全解锁即可调用。

DcmDsl

DcmDslBuffers

DcmDslBuffers 下的每个实例用于配置 DCM 模块的诊断通信缓冲区，用于存储诊断请求和响应数据。

参数名称 中文直译 / 作用 详细解释 配置要点 / 注意事项
Short Name 短名称 该缓冲区配置实例的唯一标识名。 通常保持默认，如 DcmDslBuffer。
Dsl Buffer Size [Byte] DSL 缓冲区大小 指定该诊断缓冲区的大小，以字节为单位。该缓冲区用于存放诊断请求报文和响应报文的数据。 必须足够大，能够容纳项目中最大的诊断请求或响应报文。截图中为 1024 字节，对于 UDS 诊断来说是比较常见的配置，能够支持较大的诊断数据（如 0x22/0x2E 读取/写入较大的 DID，或 0x31 例程控制的大数据块）。

  1. 缓冲区大小的影响：

    • 如果 Dsl Buffer Size 设置过小，当收到较大的诊断请求（如读取一个 500 字节的 DID）时，会导致缓冲区溢出，诊断通信失败。
    • 如果设置过大，会浪费 RAM 资源。

  2. 典型配置参考：

    • 对于标准 UDS 诊断（主要使用 0x22/0x2E 读写短数据），通常配置为 1024 字节 或 4096 字节。
    • 如果项目支持 刷写（FOTA） 或 大数据块传输（如 0x36 TransferData），可能需要配置为 4096 字节 或更大。

  3. 与其他缓冲区的关系：

    • DcmDslBuffer 是 DCM 模块的主通信缓冲区，所有诊断请求和响应都通过该缓冲区传递。
    • 如果项目使用了 DcmPageBufferCfg（页缓冲区），则页缓冲区专门用于刷写场景，而 DcmDslBuffer 用于常规诊断通信。

DcmDslCallbackDCMRequestService实例

DcmDslCallbackDCMRequestServices 用于配置 DCM 模块的诊断请求服务回调函数，当上层应用（如 SWC）需要发送诊断请求时，通过此回调与 DCM 模块交互。

参数名称 中文直译 / 作用 详细解释 配置要点 / 注意事项
Short Name 短名称 该回调配置实例的唯一标识名。 此处为 DcmDslCallbackDCMRequestService。
Dsl Callback DCM Request Service Start Fnc DSL 回调 DCM 请求服务启动函数 指定启动诊断请求服务的回调函数名称。当上层需要发起一个诊断请求时，会调用此函数。 截图中该参数配置为 DcmDslCallbackDCMRequestService，即该回调函数与当前配置同名。该函数由 RTE 或应用层实现，用于处理来自上层的诊断请求。
Dsl Callback DCM Request Service Use Port DSL 回调 DCM 请求服务使用端口 指定该回调函数使用的 端口（Port） 引用，用于 RTE 层面的连接。 通常保持为空，由工具链自动处理。

  1. 回调函数的触发场景：

    • 当应用层（SWC）需要主动发送诊断请求（如 UDS 请求）时，会通过 RTE 调用此回调函数。
    • DCM 模块通过此回调接收来自上层的诊断请求数据，并将其发送到诊断通信总线上。

  2. 与其他 DCM 回调的关系：

    • 此回调是从应用层到 DCM 的请求通道。
    • 与之对应的是 PduR 层的回调（如 PduR_DcmRxIndication），用于 DCM 接收来自总线的诊断请求。

  3. 典型配置：

    • Dsl Callback DCM Request Service Start Fnc 指向一个由 RTE 生成的函数（如 Rte_Call_Dcm_StartService）或一个自定义的应用层函数。
    • 如果项目中没有应用层主动发起诊断请求的需求（即诊断请求全部来自外部测试仪），此配置可能保持为空。

DcmDslDiagResp 实例

参数名称 中文直译 / 作用 详细解释 配置要点 / 注意事项
Short Name 短名称 该配置实例的唯一标识名。 用于在工具中识别该配置实例。
Dsl Diag Resp Max Num Of Declined Requests 诊断响应最大拒绝请求次数 指定在诊断通信过程中，DCM 允许的最大请求拒绝次数。当拒绝次数超过该值时，DCM 可能触发相应的错误处理或降级策略。 根据项目需求配置，一般建议配置为 2-5 次，防止因频繁拒绝导致诊断通信异常。
Dsl Diag Resp Max Num Resp Pend 诊断响应最大挂起响应次数 指定 DCM 在发送 NRC 0x78（响应挂起） 后，允许的最大挂起响应次数。当某个诊断服务需要较长时间处理时，DCM 可发送 NRC 0x78 告知测试仪等待，此参数限制了最多能发多少次。 一般建议配置为 2-5 次。若配置过小，测试仪可能因等待时间不足而超时；若配置过大，测试仪可能长时间等待导致通信异常。
Dsl Diag Resp On Second Declined Request 第二次拒绝请求时的响应行为 勾选后，当诊断请求被第二次拒绝时，DCM 会执行特定的响应行为（如发送特定的否定响应码或触发错误处理）。 建议勾选，以增强诊断通信的健壮性。具体行为取决于 DCM 内部实现。
Dsl Diag Resp Periodic Msg Padding Pattern 诊断响应周期消息填充模式 指定诊断响应中周期消息的填充模式，用于填充响应数据中的空白字节。 通常保持为空，使用默认填充模式（如 0x00）。特殊场景下（如需要特定填充值）可自定义。

  1. NRC 0x78（响应挂起）的作用：

    • 当诊断服务需要较长时间执行（如 0x31 例程控制执行耗时操作，或 0x22 读取大量数据）时，DCM 可以发送 NRC 0x78 告知测试仪 “正在处理，请等待”。
    • Max Num Resp Pend 限制了 NRC 0x78 的发送次数，防止测试仪无限等待。

  2. 典型配置建议：

    • Max Num Of Declined Requests：建议 2-5 次。
    • Max Num Resp Pend：建议 2-5 次。
    • On Second Declined Request：建议勾选。

  1. P2 与 P2* 的区别：

    时间参数 定义 适用场景
    P2 从测试仪发送请求到 ECU 开始发送响应之间的最大时间 所有诊断服务
    P2* ECU 发送 NRC 0x78（响应挂起）后，测试仪允许的额外等待时间 需要长时间处理的服务（如 0x31、0x22 大数据块）

  2. Tim Str P2 Server Adjust 和 Tim Str P2 Star Server Adjust 的关系：

    • 这些是调整值，用于在基础 P2/P2* 时间之上增加额外的容差。
    • 实际 P2 = 基础 P2 + Tim Str P2 Server Adjust
    • 实际 P2* = 基础 P2* + Tim Str P2 Star Server Adjust

  3. 关键引用的注意事项：

    • Dem Client Ref 必须正确引用，否则 DTC 相关功能无法工作。
    • Dsl Protocol Rx Buffer ID 和 Dsl Protocol Tx Buffer ID 必须指向有效的缓冲区实例。
    • Dsl Protocol SID Table 必须指向有效的 SID 表实例。
    • 这三个引用是 DCM 协议配置的核心，缺失任何一项都会导致诊断通信失败。

Dsp Power Down Time 断电时间 指定诊断模块在收到断电请求后，等待完成当前诊断操作的超时时间，以毫秒为单位。 根据项目需求配置，确保诊断操作在断电前能够完整完成。

  1. DID 查找过滤的作用：在复杂诊断场景中，某些 DID 仅在特定会话（如扩展会话）或特定安全等级下才可访问。启用查找过滤后，DCM 会自动根据当前会话/安全状态过滤掉不可用的 DID。

  2. 分页读取的适用场景：当 DID 数据长度超过底层通信协议（如 CAN）的单帧最大传输能力时（如读取超过 8 字节的 VIN 码），需要通过分页机制读取。Dsp Read Paged Data Page Size 定义了每页的大小，配合 0x22 服务的分页读取子功能使用。

  3. 动态 DID 的典型应用：动态 DID 用于支持运行时动态创建或修改的 DID，如诊断刷写过程中的临时数据缓冲区。Dsp Dynamically Defined Did Clear On State Change 确保状态切换时这些临时数据被正确清理。

  4. Dsp Max Did To Read 的典型值：

    • UDS 标准定义最大值为 0x0A（10 个）。
    • 实际项目中可根据总线负载和响应时间要求调整。
    • 配置过大会导致诊断响应超出底层通信协议（如 CAN TP）的最大传输能力。

DcmDspDataInfos 下的每个实例用于定义诊断服务中使用的数据信息（DataInfo），描述数据的基本属性（如数据类型、长度、缩放信息等）。DataInfo 是 DID 和 Routine 数据的基础定义单元。

DcmDspDidDefine 实例

DcmDspDidDefine 用于配置 动态 DID（Dynamically Defined DID） 的定义参数，控制动态 DID 的运行时行为。

参数名称 中文直译 / 作用 详细解释 配置要点 / 注意事项
Short Name 短名称 该动态 DID 定义配置实例的唯一标识名。 用于在工具中识别该配置实例。
Dsp Dynamically Defined Did Max Number of Elements 动态定义 DID 最大元素数量 指定该动态 DID 能够包含的最大元素数量，即该 DID 最多可以存储多少个数据元素。 根据项目需求配置，需考虑 RAM 资源的限制。配置过大会浪费内存，配置过小可能导致运行时无法存储所需数据。

DcmDspDidRange 实例

DcmDspDidRange 用于配置 DID 范围（DID Range） 的属性。DID 范围通常用于定义一组连续的 DID（如从 0x2000 到 0x20FF），并统一配置这些 DID 的访问行为，避免逐个 DID 重复配置。

参数名称 中文直译 / 作用 详细解释 配置要点 / 注意事项
Short Name 短名称 该 DID 范围配置实例的唯一标识名。 用于在工具中识别该配置实例。
Dsp Did Range Has Gaps DID 范围存在间隙 勾选后，表示该 DID 范围内存在间隙（Gaps），即范围内的某些 DID 无效或不支持访问。当测试仪请求这些 DID 时，DCM 会返回 NRC 0x31（请求超出范围）。 如果范围内的 DID 不连续，则勾选此参数。如果范围内所有 DID 均有效且连续，则不勾选。
Dsp Did Range Identifier Lower Limit DID 范围标识符下限 指定该 DID 范围的起始 DID 标识符（下限值）。 必须配置，定义该范围的起始 DID。
Dsp Did Range Identifier Upper Limit DID 范围标识符上限 指定该 DID 范围的结束 DID 标识符（上限值）。 必须配置，定义该范围的结束 DID。
Dsp Did Range Info Ref DID 范围信息引用 引用 DcmDspDidInfos 中定义的 DidInfo 实例，为该范围内的所有 DID 提供访问属性信息。 如果该范围内的所有 DID 共享相同的访问属性，则可以通过此引用统一配置。
Dsp Did Range Is Did Available Fnc DID 范围可用性检查函数 指定用于检查某个 DID 是否可用的回调函数名称。当测试仪请求范围内的某个 DID 时，DCM 调用此函数判断该 DID 当前是否可用。 仅在 DID 的可用性需要在运行时动态判断时配置。如果所有 DID 固定可用，则保持为空。
Dsp Did Range Max Data Length [Byte] DID 范围最大数据长度 指定该 DID 范围内所有 DID 的最大数据长度，以字节为单位。 用于内存分配和缓冲区管理。必须正确配置，确保能够容纳范围内所有 DID 的数据。
Dsp Did Range Read Did Fnc DID 范围读取函数 指定用于读取该范围内 DID 数据的回调函数名称。当测试仪请求读取范围内的某个 DID 时，DCM 调用此函数获取数据。 如果范围内的 DID 数据读取需要自定义逻辑，则在此配置对应的回调函数。
Dsp Did Range Use Port DID 范围使用端口 指定该 DID 范围访问时使用的 RTE 端口类型。 - USE_DATA_ASYNCH_CLIENT_SERVER：使用异步客户端/服务器端口。
- USE_DATA_SYNCH_CLIENT_SERVER：使用同步客户端/服务器端口。
- USE_DATA_SENDER_RECEIVER：使用发送器/接收器端口。
根据项目架构选择。
Dsp Did Range Write Did Fnc DID 范围写入函数 指定用于写入该范围内 DID 数据的回调函数名称。当测试仪请求写入范围内的某个 DID 时，DCM 调用此函数执行写入操作。 如果范围内的 DID 数据写入需要自定义逻辑，则在此配置对应的回调函数。

  1. DID 范围的典型应用场景：

    • 将一组相关的 DID（如所有标定参数 DID）组织为一个范围，统一管理。
    • 减少重复配置工作量，提高配置效率。
    • 支持 OEM 定义的 DID 地址空间管理。

  2. 有间隙的 DID 范围：当 Dsp Did Range Has Gaps 勾选时，范围内的某些 DID 可能是无效的（如 0x2000-0x20FF 中 0x20A0-0x20AF 未定义）。DCM 在处理请求时会通过 Dsp Did Range Is Did Available Fnc 回调函数动态判断该 DID 是否可用。

  3. 与单个 DID 配置的关系：

    • DcmDspDidRange 用于批量配置一组 DID。
    • 如果某个 DID 需要独立的特殊配置（如单独的安全等级或会话控制），则可以单独创建 DcmDspDidControl / DcmDspDidRead / DcmDspDidWrite 配置覆盖范围配置。

DcmDspDids 下的每个实例用于定义 DID（Data Identifier，数据标识符） 的具体内容，是 DID 配置的实现层。它将 DID 标识符与 DataInfo、Data 实例以及访问端口关联起来，完成 DID 的完整定义。

参数名称 中文直译 / 作用 详细解释 配置要点 / 注意事项

Dsp Did Identifier DID 标识符 该 DID 的数字标识符，即 UDS 协议中 0x22/0x2E 服务使用的 DID 值（16 位）。 必须与整车诊断规范中的定义完全一致。
Dsp Did Info Ref DID 信息引用 关键引用。引用 DcmDspDidInfos 中定义的 DidInfo 实例，为该 DID 提供访问属性信息。 必须正确引用，否则该 DID 缺少访问属性定义。

- USE_DATA_SENDER_RECEIVER：发送器/接收器。

根据项目架构选择。
Dsp Did Used DID 是否启用 勾选后，表示该 DID 在项目中启用。 必须勾选，否则该 DID 不会生效，测试仪请求时会返回 NRC 0x11（服务不支持）或 0x31（请求超出范围）。

  1. DID 的完整配置链路：

    • Dsp Did Identifier → 定义 DID 的数值（如 0xF105），对应 UDS 协议中的 DID。
    • Dsp Did Info Ref → 引用 DidInfo，定义 DID 的访问属性（是否动态定义）。
    • Dsp Did Ref → 引用 Data，定义 DID 的数据来源（信号/常量/回调）。

  2. DID 数值的约定：

    • UDS 标准中 DID 为 16 位（0x0000 - 0xFFFF）。
    • 部分范围有特殊含义：0xF000 - 0xFFFF 通常保留给 OEM 或供应商自定义。

  3. USE_DATA_ELEMENT_SPECIFIC_INTERFACES：截图中使用的端口类型表示该 DID 使用数据元素特定的 RTE 接口，即每个数据元素拥有独立的访问接口，而非通过通用的数组或结构体接口访问。

DcmDspPids 下的每个实例用于配置 OBD 服务中的 PID（Parameter ID，参数标识符） 。OBD（车载诊断系统）使用 PID 来标识不同的诊断数据，如发动机转速、车速、冷却液温度等。

    PID 名称 数据长度（字节） 说明

    0x0C 发动机转速 2 当前发动机转速
    0x0D 车速 1 当前车辆速度
    0x10 MAF 空气流量 2 质量空气流量
    0x1F 运行时间 2 发动机运行时间
    0x2F 燃油液位 1 燃油液位百分比

  3. OBD 服务分类：

    • Service 01：实时数据读取，最常用。

    • Service 03/04：DTC 读取/清除。
    • Service 06：测试结果数据（如传感器监测结果）。

DcmDspComControlAllChannel 实例

DcmDspComControlAllChannel 用于配置 通信控制（CommunicationControl，0x28 服务） 中 “所有通道” 控制模式下的目标通信通道。当测试仪请求启用或禁用所有通信通道时，DCM 通过此配置控制对应的 ComM 通道。

Short Name 短名称 该通信控制通道配置实例的唯一标识名。 用于在工具中识别该配置实例。
Dsp All ComM Channel Ref 所有通信通道的 ComM 通道引用 关键引用。引用 ComM（通信管理器） 模块中定义的通信通道配置实例，指定 0x28 服务的 “所有通道” 控制模式实际作用于哪个 ComM 通道。 必须正确引用，确保通信控制命令能够正确传递给 ComM 模块。该引用决定了执行 0x28 服务时，被控制的是哪个具体的通信通道。

  1. 0x28 CommunicationControl 服务的控制类型：

    • enableRxAndTx（0x00）：启用接收和发送。
    • enableRxAndDisableTx（0x01）：启用接收，禁用发送。
    • disableRxAndEnableTx（0x02）：禁用接收，启用发送。

  4. 典型配置场景：

    • 在诊断刷写过程中，禁用所有非诊断通信通道，以释放总线带宽。
    • 在特定诊断会话下，限制部分通信通道，以满足安全或功能需求。

DcmDspComControlSetting 实例

DcmDspComControlSetting 用于配置 通信控制（CommunicationControl，0x28 服务） 的重新启用模式规则，定义在通信被禁用后，重新启用通信的条件或方式。

Short Name 短名称 该通信控制设置配置实例的唯一标识名。 用于在工具中识别该配置实例。
Dsp Com Control Communication Re Enable Mode Rule Ref 通信控制重新启用模式规则引用 引用定义了通信重新启用模式规则的配置实例，该规则控制当通信被 0x28 服务禁用后，在什么条件下可以重新启用通信。 通常保持默认，指向一个预定义的模式规则。该规则决定了重新启用通信的触发条件（如会话切换、ECU 复位、特定事件等）。

  1. 重新启用模式规则的作用：当测试仪通过 0x28 服务禁用通信后，需要定义何时重新启用通信。该规则防止通信被永久禁用，确保 ECU 在特定条件下能够恢复正常通信。

    • DcmDspComControlSetting：定义 0x28 服务禁用通信后如何重新启用通信。
    • 两者共同构成通信控制的完整配置。

  1. 安全绕过的安全风险：Dsp Security Bypass Enabled 是高敏感参数，启用后所有安全访问保护均被禁用。必须确保量产版本中此参数为未勾选状态，否则 ECU 的安全机制完全失效。

  2. 多安全等级的独立管理：ECU 可能支持多个安全等级（如 level3、level13），每个等级有独立的种子/密钥、尝试计数器和延迟计时器。Single Instance Attempt Monitor 和 Single Instance Delay Timer 确保不同等级之间的状态互不干扰。

  3. 尝试计数器的生命周期：

    • 当安全访问尝试失败时，尝试计数器递增。
    • 当达到最大尝试次数后，ECU 增加延迟时间，防止暴力破解。
    • 当 Reset Attempt Counter On Timeout 勾选时，超时后计数器自动重置，测试仪可以重新开始尝试。

DcmDspSecurityCallback 实例

DcmDspSecurityCallback 用于配置 安全访问（SecurityAccess，0x27 服务） 的回调函数，该函数由用户实现，用于处理安全访问的种子生成和密钥验证逻辑。

参数名称 中文直译 / 作用 详细解释 配置要点 / 注意事项

Dsp Security Callback Fnc 安全回调函数 指定用于安全访问处理的回调函数名称。该函数由用户实现，负责生成种子（Seed）和验证密钥（Key）。当测试仪请求安全访问时，DCM 调用此函数执行具体的加密算法。 必须正确配置，指向用户实现的安全算法函数。如果未配置，安全访问服务将无法工作。该函数的接口需要符合 AUTOSAR 标准的安全回调函数原型。

    • 测试仪发送 Seed Request（0x01）请求种子。
    • ECU 调用 Dsp Security Callback Fnc 生成种子并返回给测试仪。
    • 测试仪使用种子计算密钥，发送 Key Send（0x02）请求。

    • Seed 生成：根据当前安全等级、随机数或时间戳生成种子值。
    • Key 验证：使用与测试仪相同的算法计算预期密钥，与测试仪发送的密钥进行比较，返回验证结果。

    • 通常 Seed Size 和 Key Size 相同（如都是 4 字节）。
    • 具体长度取决于使用的加密算法（如基于 AES 的算法通常使用 16 字节）。

  3. 尝试计数器的防暴力破解机制：

    • ECU 记录每个安全等级的失败尝试次数。
    • 每次失败后，尝试计数器递增。
    • 当达到 Num Att Delay 指定的次数后，ECU 会增加 Delay Time 的延迟。
    • 成功验证后，尝试计数器重置。
    • 这一机制有效防止了暴力破解攻击。

DcmDspSession 实例

DcmDspSession 是 DCM 模块中 诊断会话控制（DiagSessionControl，0x10 服务） 的顶层配置容器，用于配置诊断会话的全局行为参数。

参数名称 中文直译 / 作用 详细解释 配置要点 / 注意事项
Short Name 短名称 该诊断会话配置实例的唯一标识名。 用于在工具中识别该配置实例。
Session Timer S3 Enabled S3 定时器启用 勾选后，启用 S3 定时器（Session Timeout Timer） 功能。S3 定时器用于监控当前诊断会话的空闲时间，当在指定时间内未收到任何诊断请求时，ECU 自动从当前会话回退到默认会话（Default Session）。 建议勾选，这是 UDS 协议的标准行为，用于确保 ECU 不会长期停留在非默认会话（如扩展会话或编程会话），避免安全风险或资源占用。

  1. S3 定时器的作用：S3 定时器是 UDS 协议中的重要机制，用于管理诊断会话的生命周期：

    • 每次收到诊断请求时，S3 定时器重置。
    • 当 S3 定时器超时（通常为 5 秒）时，ECU 自动切回默认会话。

  2. S3 定时器的典型配置：

    • S3 定时器的超时值通常在 DcmGeneral 或 DcmDspSessionRows 中配置。
    • 典型的 S3 超时值为 5000ms（5 秒），但可根据 OEM 规范调整。

  3. 会话切换的影响：从非默认会话切换回默认会话时，ECU 会执行相应的清理操作：

    • 释放扩展会话中分配的资源。
    • 清除安全访问解锁状态（需重新进行安全访问）。
    • 恢复默认的通信控制状态。

Final Response To Fbl Enabled 向 FBL 发送最终响应启用 勾选后，DCM 在执行完相关操作后会向 FBL（Flash Bootloader） 发送最终响应。 仅在需要与 FBL 进行诊断通信时启用（如刷写场景）。
Foreign Diagnostic Request Detection Enabled 外部诊断请求检测启用 勾选后，启用外部诊断请求检测，用于识别来自外部（如其他 ECU）的诊断请求。 仅在多 ECU 诊断路由场景中需要配置。
Keep Alive Time [ms] 保持活跃时间 指定 S3 定时器（会话超时定时器） 的超时值，以毫秒为单位。当在指定时间内未收到诊断请求时，ECU 自动切回默认会话。 根据 OEM 诊断规范配置，典型值为 5000ms（5 秒）。
Keep Alive Time Start On Func 3E 80 3E 80 时启动保活计时器 勾选后，当测试仪发送 0x3E 0x80（TesterPresent，测试仪在线） 请求时，重新启动保活计时器。 建议勾选，符合 UDS 标准行为。
Main Function Worker Task Time [ms] 主函数工作任务时间 指定 DCM 的主函数工作任务（Main Function Worker Task） 的执行周期，以毫秒为单位。 根据项目调度周期配置。
Max Number Iterations Per Task 每任务最大迭代次数 指定 DCM 主函数中每次任务调用的最大迭代次数，用于控制单次任务的执行时间。 根据项目调度策略配置，防止单次任务执行过久影响系统实时性。
Max Number Of Threads 最大线程数 指定 DCM 模块支持的最大线程数，用于多线程诊断请求处理。 通常保持默认（1），除非项目需要并行处理多个诊断请求。
Parallel Protocol Processing Enabled 并行协议处理启用 勾选后，启用并行协议处理，允许多个诊断协议同时处理请求。 仅在需要并行处理多个诊断通道时启用。
Request Manufacturer Notification Enabled 厂商请求通知启用 勾选后，当收到厂商自定义的诊断请求时，DCM 会通知上层模块。 如果项目中有厂商自定义的诊断服务，则需要勾选。
Request Supplier Notification Enabled 供应商请求通知启用 勾选后，当收到供应商自定义的诊断请求时，DCM 会通知上层模块。 如果项目中有供应商自定义的诊断服务，则需要勾选。
Reset To Fbl After Session Final Response Enabled 会话最终响应后复位到 FBL 启用 勾选后，当诊断会话完成后，ECU 会复位并跳转到 FBL（Flash Bootloader） 模式。 仅在刷写场景中需要启用。
Respond All Request 响应所有请求 勾选后，DCM 对所有诊断请求都响应（即使请求格式不合法也会发送否定响应）。 通常不勾选，仅用于调试目的。
Safe Bsw Checks 安全 BSW 检查 勾选后，启用安全 BSW 检查，对关键参数进行合法性检查，用于功能安全场景。 在 ASIL 项目中建议勾选，QM 项目保持关闭以提升性能。
Security Level Change Notification Enabled 安全等级变化通知启用 勾选后，当安全访问等级发生变化时，DCM 会通知上层模块。 如果上层模块需要感知安全等级变化，则勾选。
Sender Receiver PR Ports Enabled 发送器/接收器 PR 端口启用 勾选后，启用发送器/接收器 PR 端口，允许 DCM 通过 S/R 接口与 SWC 通信。 根据项目通信架构决定。
Split Tasks Enabled 分割任务启用 勾选后，将 DCM 的长时间任务分割为多个短任务执行，防止阻塞系统调度。 建议勾选，提高系统实时性。
State Recovery After Reset Enabled 复位后状态恢复启用 勾选后，ECU 复位后 DCM 会恢复之前的诊断状态。 根据项目需求配置，通常在需要保持诊断状态的场景中启用。
Supported ID Calculation Suppression Enabled 支持 ID 计算抑制启用 勾选后，抑制支持 ID 的计算，用于优化性能。 通常保持默认（不勾选）。
Suppress Response On Can Tp Func Mixed Addr Requests 抑制对 CAN TP 功能混合地址请求的响应 勾选后，当收到 CAN TP（传输协议）的混合地址请求时，DCM 不发送响应。 根据项目需求配置，通常保持默认（不勾选）。
Task Time [ms] 任务时间 指定 DCM 主函数任务的周期，以毫秒为单位。 根据项目调度周期配置。
Typed Data Interfaces Enabled 类型化数据接口启用 勾选后，启用 类型化数据接口，DCM 通过 RTE 的类型化接口访问数据。 根据项目架构决定。
User Config File 用户配置文件 指定一个用户自定义配置文件的路径，允许用户通过外部文件覆盖部分 DCM 配置。 通常保持默认或留空。
Version Info Api 版本信息 API 勾选后，生成 Dcm_GetVersionInfo API，用于获取 DCM 模块的版本信息。 建议勾选，便于版本管理和调试。
Virtual Request Enabled 虚拟请求启用 勾选后，启用虚拟请求功能，允许在不连接实际总线的条件下测试 DCM 的诊断服务处理逻辑。 仅在开发调试阶段使用，量产版本关闭。

  1. 开发 vs 量产配置建议：

    参数 开发阶段 量产阶段
    Dev Error Detect ✅ 勾选 ❌ 关闭
    Virtual Request Enabled ✅ 勾选 ❌ 关闭
    Defensive Behavior Enabled ✅ 勾选 ✅ 勾选
    Safe Bsw Checks ✅ 勾选 ASIL 项目勾选
    Version Info Api ✅ 勾选 ✅ 勾选

  2. 大小端配置的重要性：Dsp Data Default Endianness 是全局默认值，如果所有诊断数据都使用同一种字节序，则在此处统一配置，无需在每个 DID/Data 中单独配置。如果某些数据使用不同的字节序，可以在 Dsp Data Endianness 中单独覆盖。
